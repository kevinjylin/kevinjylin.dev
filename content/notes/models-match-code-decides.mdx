---
title: "The model matches, the code decides"
date: "2026-11-16"
summary: "I didn't plan it, but every agent project I built this year ended up following the same rule."
---

I was looking back at what I built this year and noticed I kept doing the same thing without ever
meaning to: let the model handle the fuzzy part, and let plain code make the actual call.

- **Yardsale.** Claude's only job is figuring out which past eBay sales are the same product. The
  asking price and the floor come from code.
- **Highlander Hub.** Gemini decides if an Instagram post is an event, but it has to point to the
  caption or slide that says so. Code checks that it really does, and if it doesn't, the answer gets
  thrown out.
- **SpyGlass.** We only highlight a claim in the tweet once code confirms that exact text is
  actually in the post. The overall verdict is just code too.
- **Second Grader.** Models pull claims out of the agent's messages and write tests, but whether
  "all tests pass" is true is never up to an LLM. Code decides that.

## Why I keep doing it

Models are great at reading messy stuff, but I can't hold them accountable for it. Code is the
opposite. Splitting it up this way means anything a user sees traces back to something real: a
sale, a slide, a sentence, a test run.

## The catch

It's more plumbing. Every project needed a check that could say no, and then I had to decide what
happens when it does: refuse, fall back to a link, or just ask the user instead of guessing.
